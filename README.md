# Klick Desk

Личный планировщик на React: задачи по агентству, контенту и учёбе, таймер фокуса и погода в Алматы. Индивидуальный проект для мидтерма и Task 4. Effects.

- [Приложение](https://tamerlanta.github.io/klick-desk/)
- [Публичный репозиторий](https://github.com/TamerlanTA/klick-desk)

## Возможности

- Основной список из 100 начальных записей и отдельный просмотр задачи с описанием и всеми полями.
- Добавление, редактирование, отметка выполнения, удаление с подтверждением.
- Управляемая форма: название, описание, направление, приоритет, срок. Проверка названия (3–120 символов), описания (до 1000 символов) и календарной даты.
- Поиск по названию и описанию с debounce 300 мс; совместные фильтры по направлению и статусу.
- Сортировка по новизне, сроку, приоритету или названию. Пагинация по 6, 12 или 24 задачи.
- Состояния загрузки, ошибки с повтором, пустого результата и успешного сохранения.
- Сохранение задач и настроек сортировки/размера страницы между перезагрузками.
- Общая статистика по всем задачам, независимо от страницы и фильтров.
- Таймер на 5, 15 или 25 минут: старт, пауза, продолжение, сброс. Маскот Клик меняет состояние при фокусе и выполнении всех задач.
- Погода Алматы из публичного API с загрузкой, ошибкой, таймаутом и повторным запросом.
- Адаптивный интерфейс на обычном CSS, локальные изображения и шрифт Onest.

## Запуск

Стек: React + Vite, JavaScript, plain CSS. Сервер и платные API не нужны. Проверено на Node.js 26.0.0 и npm 11.12.1.

```bash
git clone https://github.com/TamerlanTA/klick-desk.git
cd klick-desk
npm ci
npm run dev
```

Открыть адрес из терминала, обычно `http://localhost:5173/klick-desk/`.

```bash
npm run build    # сборка в dist/
npm run preview  # локальная проверка production-сборки
npm run lint     # проверка JavaScript и правил hooks
npm test         # 24 теста
```

## Основной источник данных

`src/api/taskApi.js` — симулированный API задач. Все методы возвращают Promise с задержкой 250 мс: `list`, `get`, `create`, `update`, `remove`. Это основной источник данных и для списка, и для детального просмотра. Начальный набор находится в `src/data/tasks.json`: ровно 100 записей с уникальными ID, названием, описанием, направлением, приоритетом, сроком, статусом и временем создания.

`list` сначала применяет поиск и фильтры ко всему набору, затем сортировку и только потом пагинацию. Ответ содержит текущие записи, число результатов, номер и количество страниц, общую статистику. При изменении фильтра страница сбрасывается на первую; после удаления последней записи на странице API ограничивает номер существующей страницей. `get(id)` отдельно загружает одну задачу.

Изменения сохраняются под ключом `klick-desk.tasks.v2` в формате `{ version: 2, tasks: [...] }`. Начальные записи создаются только при отсутствии хранилища. Сохранённый пустой массив остаётся пустым. При переходе с первой версии старые задачи сохраняются и дополняются начальным набором; прежняя запись остаётся резервной копией. Повреждённые данные не перезаписываются: список показывает ошибку и кнопку повтора. Ошибка записи также отображается, операция не выдаётся за успешную.

Данные принадлежат текущему браузеру и origin; между устройствами они не синхронизируются. Настройки сортировки и размера страницы хранятся отдельно: `klick-desk.settings.v1`. Поиск, выбранная задача и таймер при перезагрузке сбрасываются.

Погода — дополнительный виджет для задания на fetch: [Open-Meteo](https://open-meteo.com/en/docs), координаты Алматы, часовой пояс Asia/Almaty. Ключ не требуется. Сбой погоды не блокирует основной список и таймер.

## Поток данных

`App → useTasks → taskApi.list → TaskList → TaskItem`. Параметры запроса поднимаются в App, результат хранится в hook. Форма держит локальный черновик и после валидации вызывает обработчик родителя. API сохраняет изменение, затем App запрашивает обновлённый список. Отдельной копии списка в форме или сводке нет.

`TaskDetails` загружает данные по ID. Запросы чтения отменяются при cleanup; флаг активности дополнительно блокирует запоздалые ответы. Пока запись выполняется, кнопки блокируются. Маскот получает isFocusing и allCompleted через props; выбирать изображение можно при рендере без эффекта.

## Публикация

```bash
npm run deploy
```

`predeploy` собирает приложение, затем gh-pages публикует dist в ветку gh-pages. Настройка GitHub Pages: ветка gh-pages, каталог `/`. Исходники отдельно коммитятся и отправляются в main. Имя репозитория и base должны совпадать. Список и детальный просмотр переключаются состоянием React, вложенных URL нет.
