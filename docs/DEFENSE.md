# Защита Jarvis Desk — 3–4 минуты

Перед началом открыть [приложение](https://tamerlanta.github.io/jarvis-desk/) и исходники `App.jsx`, `useStoredTasks.js`, `WeatherWidget.jsx`, `FocusTimer.jsx`. Проверить сеть для демонстрации погоды.

## 0:00–0:25 — Что это

«Я сделал Jarvis Desk — личную панель, которая помогает держать в одном месте задачи по агентству, контенту и учёбе. Здесь есть список дел, прогресс выполнения, таймер фокуса и погода в Алматы. Это статическое React-приложение на Vite и JavaScript, опубликованное на GitHub Pages».

## 0:25–1:10 — Демо №1: задача и сохранение

Нажать «Новая задача». Отправить пустую форму: показать сообщение валидации. Ввести «Подготовить презентацию», выбрать «Учёба» и сохранить. Отметить выполнение: процент и счётчики изменятся. Обновить страницу: задача останется.

«Форма управляемая: значения находятся в state и меняются через onChange. onSubmit отменяет стандартную отправку, проверяет данные и передаёт их родителю через onSave. Задачи хранятся на уровне App через пользовательский hook. Список и сводка получают одни и те же данные через props — это lifting state up».

## 1:10–1:40 — Демо №2: поиск и фильтры

Выбрать «Учёба» и «Готово». Ввести часть названия в поиск. Затем несуществующее слово, показать пустой результат и нажать «Сбросить фильтры».

«У поиска, направления и статуса независимые useState. Фильтры применяются вместе. Список строится через map, ключ — постоянный ID задачи. Поиск использует debounce: результат меняется после 300 мс без ввода. Предыдущий timeout очищается в cleanup».

## 1:40–2:10 — Демо №3: фокус и погода

Выбрать 5 минут, нажать «Начать», показать уменьшение времени, поставить на паузу и сбросить. Нажать обновление погоды: кратко показать загрузку и данные.

«Таймер хранит время окончания и вычисляет остаток относительно системных часов. Это помогает при замедлении фоновой вкладки. Когда таймер останавливается или компонент удаляется, cleanup вызывает clearInterval. Погода загружается из публичного Open-Meteo API; у неё есть состояния загрузки, результата и ошибки с повтором».

## 2:10–3:10 — Где state и effects в коде

Открыть соответствующие файлы и показать:

1. **`App.jsx`:** state фильтров и диалогов; задачи получены из `useStoredTasks`; обработчики передаются вниз через props. Сводка и видимый список вычисляются при рендере.
2. **`useStoredTasks.js`:** первый effect с `[]` читает данные. Второй с `[tasks, canSave]` сохраняет их. Флаг блокирует запись до окончания чтения, чтобы не затереть старые задачи.
3. **`WeatherWidget.jsx`:** effect зависит от `requestNumber`. Проверяет HTTP-ответ и JSON, обрабатывает ошибки. Cleanup отменяет fetch через AbortController и очищает таймаут.
4. **`FocusTimer.jsx`:** effect зависит от `endsAt`, создаёт интервал и возвращает функцию очистки.

«Эффекты нужны там, где React синхронизируется с браузерным хранилищем, сетью или временем. Валидация и изменение задач относятся к событиям, поэтому выполняются в обработчиках».

## 3:10–3:35 — Проверка и публикация

«В проекте 10 отдельных компонентов, JavaScript и обычный адаптивный CSS. Проходят npm run build, npm run lint и 12 тестов. Тесты проверяют сохранность данных, очистку таймеров и восстановление после ошибки API. В Vite задан base для имени репозитория; npm run deploy сначала собирает приложение, затем публикует dist в ветку gh-pages».

## Короткие ответы на вероятные вопросы

| Вопрос | Ответ |
| --- | --- |
| Почему state задач поднят? | Он нужен одновременно списку, форме через обработчики и сводке. Общий владелец исключает разные копии одного списка. |
| Почему нельзя менять массив через push? | Создаём новый массив через spread, map или filter, чтобы React получил новое значение и сохранился предсказуемый поток данных. |
| Зачем key? | Помогает React сопоставлять элементы при добавлении и удалении. ID стабилен, индекс может измениться. |
| Зачем cleanup? | Чтобы старые интервалы, таймауты и запросы не продолжали работать после изменения зависимостей или удаления компонента. |
| Что означает []? | В обычном жизненном цикле effect запускается после первого рендера. В StrictMode при разработке есть дополнительная проверка setup/cleanup. |
| Почему эффект погоды зависит от requestNumber? | Нажатие обновления меняет счётчик и повторно запускает синхронизацию с API. |
| Что будет без сети? | Виджет погоды покажет ошибку и кнопку повторной загрузки. Уже открытые задачи и таймер продолжают работать. |
| Почему таймер сбросился после перезагрузки? | Его state хранится в памяти компонента. В localStorage сохраняются только задачи. |
| Почему нет роутера? | У приложения один экран. Для него маршрутизация не нужна. |
| Есть ли AI? | Здесь реализована персональная панель задач в стиле Джарвиса. Для текущих функций достаточно React и открытого API погоды. |
