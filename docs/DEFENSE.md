# Защита Klick Desk — 3–4 минуты

Открыть [приложение](https://tamerlanta.github.io/klick-desk/) и исходники App.jsx, api/taskApi.js, hooks/useTasks.js, hooks/useTaskSettings.js, components/TaskForm.jsx, components/FocusTimer.jsx. Для погоды нужна сеть. В новом браузере список содержит 100 записей; существующие пользовательские данные сохраняются.

## 0:00–0:25 — Приложение и источник данных

«Klick Desk — личный планировщик задач по агентству, контенту и учёбе. Здесь можно найти задачу, открыть подробности и изменить её. Основной источник — симулированный Promise API с JSON из 100 записей. Изменения сохраняются в браузере. Приложение написано на React, Vite и JavaScript и работает статически на GitHub Pages».

## 0:25–1:10 — Демо 1: большой список и детали

Показать общий счётчик, перейти на вторую страницу, выбрать сортировку по названию: страница сбросится на первую. Выбрать «Учёба», ввести «Курс React» и открыть задачу нажатием названия. Показать описание, срок, приоритет, статус и ID, вернуться к списку.

«Поиск и фильтры применяются ко всему набору, затем сортировка и пагинация. API возвращает записи и метаданные страниц. Детальный просмотр делает отдельный get по ID. Во время запроса видна загрузка; при ошибке доступен повтор».

## 1:10–1:55 — Демо 2: форма и сохранение

Нажать «Новая задача», отправить пустое название и показать ошибку. Заполнить «Подготовить защиту», описание, направление «Учёба» и сохранить. Новая задача появится первой. Открыть её, показать описание, вернуться и отметить выполнение. Обновить страницу: задача останется.

«Форма управляемая: значения в локальном state, onChange обновляет поле, onSubmit отменяет обычную отправку и проверяет данные. Обработчик App вызывает API; сообщение об успехе появляется после сохранения. Общие фильтры и выбранный ID подняты в App; список и сводка используют один результат hook, данные и callbacks идут через props».

## 1:55–2:25 — Демо 3: фокус и эффекты

Выбрать 5 минут, начать фокус, показать изменение маскота и времени, поставить на паузу, сбросить. Обновить погоду.

«Эффект таймера создаёт интервал и возвращает clearInterval. Остаток считается от времени окончания. Погода использует настоящий fetch с loading/error, AbortController и таймаутом. Поиск использует отдельный timeout с cleanup для debounce».

## 2:25–3:25 — Код и жизненный цикл

Показать четыре участка:

1. App.jsx: параметры списка, выбранный ID и props. TaskForm хранит только черновик. Постоянный ID используется как key, форма получает key ID или new для корректного сброса локального состояния.
2. useTasks.js: зависимости запроса, loading/error/success, AbortController и active. Cleanup блокирует старый ответ при смене запроса или unmount.
3. useTaskSettings.js: чтение localStorage с [], запись при изменениях сортировки и размера страницы; loaded предотвращает запись до начального чтения.
4. taskApi.js: Promise API, 100 записей из JSON, фильтрация → сортировка → slice; CRUD сохраняет данные только после валидации.

«Рендер вычисляет JSX из текущих props и state. Commit применяет изменения к DOM. Effects синхронизируют уже закоммиченный компонент с внешними системами. Обработчик видит снимок state своего рендера; для счётчика повтора используется функциональное обновление. React группирует несколько обновлений, поэтому не нужен ручной вызов рендера».

## 3:25–3:45 — Проверка и публикация

«В проекте 13 компонентов, обычный адаптивный CSS и семь эффектов. Проходят сборка, lint и 24 теста: API, формы, гонки запросов, хранилище и cleanup. В Vite base совпадает с именем репозитория, gh-pages публикует production-сборку. Список и детали переключаются через state без вложенных URL».

## Вопросы по React

| Вопрос                             | Ответ на примере проекта                                                                                                                                                                    |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Кто владеет state?                 | App — общие параметры и представления; useTasks — результат запроса; TaskForm — черновик; FocusTimer — отсчёт. Это исключает независимые копии одного списка                                |
| Почему props нельзя изменять?      | Они принадлежат родителю. TaskItem сообщает событие через callback; родитель вызывает API и загружает новый результат                                                                       |
| Что такое snapshot?                | Обработчик замыкает значения своего рендера. После setState локальная переменная сразу не меняется. Когда новое значение зависит от предыдущего, используем setRevision(value => value + 1) |
| Что такое batching?                | React объединяет обновления. В changeFilter setter(value) и setPage(1) приводят к согласованным параметрам следующего рендера                                                               |
| Зачем key?                         | React сопоставляет соседние элементы по типу и key. ID остаётся связан с задачей при сортировке, индекс меняется. Новый key формы означает новый экземпляр и новый черновик                 |
| Что сохраняет локальное состояние? | Тот же тип компонента на той же позиции с тем же key. Таймер остаётся на месте при переключении списка/формы/деталей и продолжает отсчёт                                                    |
| Render, commit, effect?            | Render вычисляет дерево; commit обновляет DOM; effect запускает внешнюю синхронизацию после commit. В render нет записи в storage или запроса                                               |
| Что такое stale closure?           | Callback сохраняет значения рендера, в котором создан. Таймер читает endsAt из актуального запуска эффекта; зависимости перезапускают его, cleanup удаляет старый интервал                  |
| Почему abort и active вместе?      | Abort отменяет операцию, active не допускает позднюю запись в state даже у источника, который проигнорировал signal                                                                         |
| Что означает []?                   | После первого commit компонента. В StrictMode разработки есть дополнительный setup/cleanup. Это не обещание единственного вызова за всю жизнь приложения                                    |
| Почему CRUD не в effect?           | Он вызван конкретным событием пользователя. Effect списка отвечает за синхронизацию запроса с параметрами; повторный effect записи дублировал бы операцию                                   |
| Можно ли мутировать массив?        | Нельзя менять данные state/props на месте. API создаёт новые массивы через filter/map/spread. sort применяется к новому массиву, полученному filter                                         |
| Зачем loaded в настройках?         | Чтобы начальное значение по умолчанию не записалось поверх сохранённого до чтения                                                                                                           |
| Что без сети?                      | Задачи и таймер работают локально; погода показывает ошибку и повтор. Это симулированный API, а не настоящий сервер                                                                         |
| Почему нет роутера?                | Два представления переключаются через selectedId. Для них не нужны разные адреса; перезагрузка возвращает список                                                                            |

После изменения запустить сборку и проверить конкретный изменённый сценарий. Перед защитой самостоятельно пройти все три демо и найти указанные участки кода без поиска по всему проекту.
