## Загрузка и сохранение localStorage

Первый effect useTaskSettings читает сохранённые сортировку и размер страницы. Допустимые значения проверяются. Затем устанавливает loaded = true. Второй effect до этого ничего не пишет: начальные значения не должны затереть настройки раньше чтения. После загрузки он сохраняет изменения sort и pageSize.

Проверка: выбрать сортировку по названию и 12 задач на странице, обновить страницу. Оба значения восстановятся. Хранилище настроек: klick-desk.settings.v1.

Задачи тоже сохраняются между перезагрузками, но принадлежат основному API. taskApi.list/get читают klick-desk.tasks.v2, а create/update/remove записывают его. Запись запускается событием пользователя, поэтому отдельный effect для неё не нужен. API может сообщить об ошибке сохранения до показа успешного результата.

## Основной API и защита от гонок

При изменении параметров useTasks устанавливает loading и вызывает taskApi.list с AbortSignal. API возвращает Promise через 250 мс. При успехе hook обновляет результат и статус, при ошибке — сообщение и error. Кнопка повтора увеличивает revision функциональным обновлением.

Cleanup выполняется перед следующим запуском эффекта и при unmount. Он отменяет ожидание API и делает локальный флаг active ложным. Даже если источник проигнорирует отмену, старый ответ не обновит state. Это защищает от ситуации, когда ответ на старый поиск приходит после ответа на новый.

TaskDetails использует тот же принцип для get(id). Выбор ID хранится в App; редактирование и детальный просмотр — разные представления.

## Публичный fetch

Effect погоды запускается при монтировании и изменении requestNumber. Последовательность: loading → fetch с signal → проверка response.ok → JSON → проверка структуры → данные. Сеть, HTTP-ошибка, неверный ответ и таймаут приводят к сообщению с кнопкой повтора.

Таймаут через 12 секунд вызывает abort. Cleanup отменяет запрос и таймаут, а isActive блокирует запись устаревшего результата. В finally таймаут также удаляется. Погода не участвует в фильтрации задач: основной источник списка — API задач.

## Таймер и cleanup

Старт задаёт абсолютное endsAt = Date.now() + remaining * 1000. Effect создаёт интервал каждые 200 мс, пока endsAt не равен null. Остаток вычисляется от системного времени, а не вычитанием единицы из замкнутого значения state.

Пауза сохраняет остаток и устанавливает endsAt в null; cleanup удаляет интервал. Сброс, смена длительности и unmount также освобождают его. На нуле таймер останавливается. Callback onRunningChange связывает таймер с маскотом; App передаёт стабильный setter состояния.

## Debounce

Поле поиска сразу обновляет search, поэтому остаётся отзывчивым. Hook откладывает обновление debouncedValue на 300 мс. Новый ввод очищает предыдущий timeout, unmount — последний активный. Затем useTasks запрашивает результаты с новым значением.

## Что выполняется без effect

Валидация и CRUD запускаются обработчиками событий. Фильтрация, сортировка, пагинация и общая статистика вычисляются внутри API при запросе; выбор изображения маскота — во время рендера по props. Эффект не нужен, чтобы просто вычислить одно значение из другого.

## StrictMode и проверки

В main.jsx включён StrictMode. В разработке дополнительный цикл setup → cleanup → setup проверяет очистку. Отменённый первый запрос допустим; второй должен корректно завершиться. Массив зависимостей описывает все реактивные значения, прочитанные эффектом.

npm test проверяет cleanup таймера и debounce с виртуальным временем, abort и stale responses с управляемыми Promise, сохранение настроек, ошибки/повтор запросов и сохранность задач. Реальная сеть для тестов не нужна.
