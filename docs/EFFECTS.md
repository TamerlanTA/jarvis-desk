# Эффекты и асинхронность

Приложение использует только useState и useEffect, без собственных хуков и debounce.

## Список — App.jsx

Effect запускает taskApi.list при изменении `[search, category, status, sort, page, pageSize, revision]`. Сначала устанавливает loading, после ответа — данные и success, после ошибки — сообщение и error. Reload увеличивает revision функциональным обновлением.

Каждый запуск создаёт AbortController и локальный active. Cleanup устанавливает active=false и отменяет запрос. Даже если провайдер игнорирует отмену, active предотвращает применение старого результата. Новый ввод сразу меняет search; предыдущий запрос очищается без debounce.

## Подробности — TaskDetails.jsx

Effect зависит от `[id, revision]`. Отдельный get загружает полную запись, включая дату создания, которой нет в списке. Cleanup отменяет запрос и блокирует его обработчики. App также задаёт key={selectedId}, поэтому состояние разных карточек не смешивается.

## Stale closures и изменение статуса

Обработчик toggleTask сохраняет itemId из переданной задачи до await и отправляет update для этого ID. Он не читает выбранный ID после ответа. Пока запрос выполняется, busy отключает конфликтующие действия. Карточка получает ответ и применяет его только к совпадающему ID. Если пользователь вернулся к списку, действие всё равно завершает исходную задачу и обновляет список. Создание/удаление/редактирование запускаются событиями, а не эффектом.

## Настройки — App.jsx

Ленивый инициализатор useState(readSettings) читает настройки через отдельный модуль API. Effect с `[sort, pageSize]` сохраняет их через saveSettings. Компоненты не обращаются к localStorage напрямую.

## Таймер и погода

FocusTimer создаёт интервал, а cleanup вызывает clearInterval. WeatherWidget загружает погоду через fetch, обрабатывает ошибки и очищает таймаут/AbortController при повторе или размонтировании.

## Имитация сети

Каждый запрос имеет задержку 200–699 мс и вероятность ошибки 5%. Ошибка возникает до чтения/записи операции, поэтому неуспешная запись не меняет данные. Кнопка «Проверить ошибку API» гарантирует ошибку следующего запроса списка. Abort отменяет таймер до выполнения операции.

В StrictMode React в разработке дополнительно проверяет цикл setup → cleanup → setup. Отмена и active делают повтор безопасным.
