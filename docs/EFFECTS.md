# Task 4. Effects — Jarvis Desk

В проекте пять вызовов `useEffect`. Каждый синхронизирует React с внешним состоянием или временем. Логика выполняется в работающем приложении.

| № | Файл | Зависимости | Внешняя система | Cleanup |
| --- | --- | --- | --- | --- |
| 1 | `src/hooks/useStoredTasks.js` — первый effect | `[]` | чтение `localStorage` при старте | не нужен: синхронная операция |
| 2 | `src/hooks/useStoredTasks.js` — второй effect | `[tasks, canSave]` | запись изменённого списка в `localStorage` | не нужен: синхронная операция |
| 3 | `src/components/WeatherWidget.jsx` | `[requestNumber]` | HTTP-запрос Open-Meteo и 12-секундный таймаут | `controller.abort()`, `clearTimeout`, флаг `isActive = false` |
| 4 | `src/components/FocusTimer.jsx` | `[endsAt]` | системные часы и интервал | `clearInterval(intervalId)` |
| 5 | `src/hooks/useDebouncedValue.js` | `[value, delay]` | таймаут debounce поиска | `clearTimeout(timeoutId)` |

## 1–2. Загрузка и сохранение

На первом рендере `tasks` пуст, а `canSave` равен `false`. Первый effect читает и проверяет данные. Если ключ отсутствует, он создаёт демонстрационный список. Уже сохранённый `[]` считается корректными данными и остаётся пустым.

После успешного чтения устанавливается `canSave = true`. Второй effect сохраняет список при изменении `tasks`. Этот флаг нужен, чтобы начальное пустое состояние не затёрло ранее сохранённые задачи. React объединяет обновления состояния из первого эффекта перед следующим рендером.

Если JSON или структура повреждены, исходная запись остаётся нетронутой, а UI сообщает о работе в памяти вкладки. Ошибка записи также отображается пользователю. В хранилище есть версия схемы и проверка уникальности ID.

## 3. Погода: loading → data / error

При монтировании и нажатии обновления запускается effect. Кнопка изменяет `requestNumber`, который находится в массиве зависимостей.

Алгоритм: установить loading, очистить ошибку, вызвать `fetch` с `AbortController.signal`, проверить `response.ok`, прочитать JSON, проверить числовые поля и записать ответ в state. Ошибки сети, HTTP и структуры ответа переходят в error. В `finally` снимается loading и удаляется таймаут.

После 12 секунд ожидания запрос отменяется и показывается сообщение о таймауте. Cleanup при повторном запуске или размонтировании отменяет запрос и таймаут. `isActive` не позволяет старому асинхронному ответу обновить состояние после cleanup. Кнопка «Повторить» запускает новый запрос.

## 4. Таймер и cleanup

Обработчик старта вычисляет абсолютное время окончания: `Date.now() + secondsLeft * 1000`. Effect зависит от `endsAt`. Когда `endsAt === null`, интервал не создаётся.

Каждые 200 мс вычисляется остаток от системного времени. Это уменьшает погрешность, возникающую при замедлении таймеров в фоновой вкладке. На нуле значение ограничивается `0`, таймер останавливается и выводит сообщение о завершении.

Пауза сохраняет остаток и устанавливает `endsAt = null`. React выполняет cleanup предыдущего эффекта и удаляет интервал. Сброс, смена длительности и unmount также очищают его. Длительность не сохраняется между перезагрузками страницы.

## 5. Debounce

`search` обновляется при каждом вводе, поэтому input остаётся управляемым и отзывчивым. Hook создаёт таймаут, который через 300 мс обновляет `debouncedValue`; по этому значению фильтруется список.

При следующем символе React сначала вызывает cleanup предыдущего запуска. Старый таймаут удаляется, а новый начинает ожидание заново. При unmount последний таймаут тоже удаляется.

## Почему не всё находится в эффектах

Валидация и создание задачи запускаются обработчиком `onSubmit`. Статистика и фильтрация — обычные вычисления по `tasks`. Им не нужна синхронизация с внешней системой, поэтому `useEffect` там не используется.

## StrictMode

В `src/main.jsx` включён `StrictMode`. В режиме разработки React выполняет дополнительный цикл setup → cleanup → setup, чтобы выявлять ошибки очистки. Первый запрос погоды может быть отменён, после чего запускается новый. Это ожидаемое поведение разработки. Тесты проверяют отсутствие потери сохранённых задач и лишних интервалов.
